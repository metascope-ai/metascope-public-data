# MetaScope CS2 — Public Prediction Archive

Открытый архив прогнозов и результатов аналитической системы MetaScope для матчей Counter-Strike 2.

Цель репозитория — хранить проверяемую историю работы моделей без удаления неудачных прогнозов и без выборки результатов задним числом.

## Данные

### Полная история бота

- [`data/bot_predictions.csv`](data/bot_predictions.csv)
- [`data/bot_predictions.json`](data/bot_predictions.json)

Содержит все завершённые решения основной модели, которые были зафиксированы системой.

В архив включены не только расчётные ставки, но и прогнозы, которые были пропущены фильтрами системы.

### Прогнозы публичного Telegram-канала

- [`data/public_channel_predictions.csv`](data/public_channel_predictions.csv)
- [`data/public_channel_predictions.json`](data/public_channel_predictions.json)

Содержит только прогнозы, которые фактически были опубликованы в публичном Telegram-канале MetaScope.

## Основные поля

`experiment_version`  
Версия эксперимента: `paper_v1`, `paper_v2`, `paper_v3` и т.д.

`prediction_created_at`  
Время создания прогноза моделью.

`decision_created_at`  
Время принятия решения системой.

`model_version`  
Версия модели, сделавшей прогноз.

`team1_name`, `team2_name`  
Участники матча.

`predicted_winner_name`  
Победитель, выбранный моделью.

`model_probability`  
Вероятность победы выбранной команды по оценке модели.

`selection_odds`  
Коэффициент, доступный на момент принятия решения, если линия была доступна.

`edge`  
Разница между вероятностью модели и оценкой рынка.

`prediction_result`  
Фактический результат прогноза модели:

- `win` — модель правильно определила победителя;
- `loss` — модель ошиблась;
- пустое значение — матч ещё не рассчитан или результат отсутствует.

`decision_status`  
Решение торгового/ставочного фильтра системы.

Возможные значения включают:

- `pending` — решение принято, результат ещё ожидался;
- `win` — расчётная ставка выиграла;
- `loss` — расчётная ставка проиграла;
- `skipped_low_odds` — коэффициент был ниже установленного порога;
- `skipped_high_odds` — коэффициент был выше установленного порога;
- `skipped_no_value` — рассчитанного преимущества над рынком было недостаточно;
- `skipped_no_line` — подходящей букмекерской линии не было;
- `skipped_roster_uncertain` — недостаточная уверенность в составе команды;
- `void_roster_change` — решение отменено из-за изменения состава.

## Важно о `decision_status`

`decision_status` и `prediction_result` — разные показатели.

Например, модель могла правильно определить победителя, но система могла не использовать прогноз из-за отсутствия линии или недостаточного преимущества над рынком.

Поэтому для оценки качества самой модели следует использовать `prediction_result`, а для анализа стратегии принятия решений — `decision_status`, коэффициенты, stake и profit.

Некоторые старые записи ранних экспериментальных версий могут сохранять исторический `decision_status = pending`, даже если результат матча уже известен. В таких случаях итог прогноза следует смотреть в `prediction_result`.

## Версии эксперимента

Архив содержит несколько поколений системы:

- `paper_v1`
- `paper_v2`
- `paper_v3`

Они отличаются логикой фильтрации, моделями и используемыми признаками. Поэтому результаты разных версий рекомендуется анализировать отдельно.

## Форматы

CSV предназначен для Excel, LibreOffice, pandas и других аналитических инструментов.

JSON предназначен для программного доступа и будущего публичного веб-интерфейса MetaScope.

## Обновление

Архив формируется автоматически из рабочей базы MetaScope.

Новые прогнозы не публикуются до завершения соответствующего матча.

После появления подтверждённого результата прогноз и его фактический исход добавляются в публичный архив при следующем автоматическом обновлении.
